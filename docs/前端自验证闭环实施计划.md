# 前端自验证闭环实施计划

**文档状态**：实施中 ｜ **适用范围**：任意本地 Web 前端项目 ｜ **首个验证项目**：Personal Agent Web

## 1. 目标

建设一条可重复、可追溯的前端验证闭环：

```text
修改前端 → 静态检查 → 启动服务 → 浏览器交互 → 截图审查 → 自动修复与复验 → 输出验证报告
```

硬性结论来自类型检查、测试、构建、DOM/交互断言、页面异常、控制台错误与关键网络失败；截图和视觉模型用于补充发现遮挡、溢出、错位和明显的视觉回归。

## 2. 项目配置

验证配置统一保存到全局 `~/.personal-agent/validation.yaml`，配置开发服务器、检查命令、浏览器视口、验证 profile 和声明式场景。所有项目默认读取这份全局配置；需要临时使用其他配置时，可通过 `pa validate -c <config-path>` 显式覆盖。命令和服务器进程仍以当前项目根目录作为工作目录，因此配置中的相对命令按当前项目执行。

视觉模型采用 Personal Agent 全局配置，不随项目切换：在“设置 → 通用 → 视觉模型”中配置启用状态、视觉供应商、支持图片输入的模型和审查提示词，持久化到 `~/.personal-agent/config.yaml` 的 `vision` 节点。页面只展示已经配置且模型元数据包含 `ImageInput` 能力的选项；仓库内 `.personal-agent/config.yaml` 不能覆盖全局视觉模型。除验证截图审查外，当任务模型不支持图片输入时，全局视觉模型会先提取用户图片中的文字与客观视觉信息，再与用户文字合并后交给任务模型。

第一版支持以下场景动作：

- `click`
- `fill`
- `press`
- `select`
- `check`
- `uncheck`
- `wait`
- `visible / hidden / text / url / count` 断言
- 场景级截图
- 全局控制台、页面异常和网络失败断言

元素定位支持 `role + name`、`text`、`testId` 和 `selector`，交互动作必须唯一命中元素。

## 3. 工具与命令

Agent 获得以下浏览器工具：

- `browser_open`
- `browser_snapshot`
- `browser_act`
- `browser_screenshot`
- `browser_close`
- `frontend_validate`

开发者可通过下列命令重放同一套验证：

```text
pa validate [--profile quick|full] [-c <config-path>] [--json]
```

退出码约定：

- `0`：硬断言全部通过；视觉警告不改变退出码。
- `1`：类型检查、测试、构建或浏览器断言失败。
- `2`：配置、浏览器或服务器启动等基础设施错误。

## 4. 运行与产物

- 使用固定版本 Playwright Chromium，并由桌面发行版携带匹配的浏览器资源。
- 验证产物保存到 `~/.personal-agent/validation-runs/<project-hash>/<run-id>/`。
- 每个项目默认保留最近 20 次运行。
- 每次运行输出 JSON report、server log、关键截图和 Playwright trace。
- Web 时间线以“前端验证”卡片展示检查结果、场景步骤、错误与产物入口。
- 视觉模型未配置或当前模型不支持图片时，仍完成所有结构化验证，并明确标记“未执行视觉审查”。

## 5. 自动触发

- 修改 `.tsx/.jsx/.vue/.svelte/.css/.scss/.less/.html` 后，Agent 在结束任务前执行 `quick` 验证。
- 使用代码差异指纹避免没有新修改时重复验证；同一文件再次修改会产生新指纹。
- 硬断言失败时允许 Agent 根据结构化证据修复并复验，最多两次。
- 首次执行项目声明的启动或检查命令时遵循现有工具权限机制。

## 6. Personal Agent 首批场景

- 首屏正常加载。
- 项目与任务导航可用。
- 设置弹窗可以打开并完整显示。
- 明暗主题可以切换。
- 输入框和发送流程可用。
- 页面、控制台和关键网络请求无异常。
- 验证环境使用隔离的临时数据与 fake provider，不产生真实模型请求费用。

## 7. 测试矩阵

- 单元测试：配置解析、触发规则、定位器、退出码、产物清理、差异指纹。
- 集成测试：服务器启动、超时、端口复用、中断及 Windows 子进程清理。
- 浏览器测试：会话隔离、外部 URL 拒绝、模糊定位失败、截图和 trace。
- Agent 测试：自动触发、失败修复、最多两次复验和防重复验证。
- 验收测试：修改可见 CSS 后自动产生截图报告；引入控制台错误或隐藏关键按钮时验证必须失败并提供定位证据。

## 9. 首期边界

- 支持浏览器可访问的本地 Web UI，不操作 Electron 原生标题栏、安装器和系统托盘。
- 第一版不接入 CI，但命令和退出码保持 CI-ready。
- 不维护像素级 golden baseline。
- 不整体重构 `App.tsx`，仅为关键流程补充稳定的可访问名称或 `data-testid`。
